Everything a Node project needs, client-side

No server to host, scale or pay for. Your users bring the compute.

Real processes

One Web Worker per PID with stdout, stderr, stdin and kill(). Child processes are workers too, supervised by a kernel.

Node's own runtime

Node v24's lib/ runs unmodified on a native layer for the browser: fs, streams, http, net, ESM and require(esm).

npm install, in the tab

A built-in npm installs from the real registry into an in-memory filesystem, then npm run starts your scripts.

Dev servers in an iframe

A Service Worker relays an iframe to a server in the sandbox, WebSockets included, so hot reload just works.

Projects that persist

Optionally mirror the filesystem to the Origin Private File System and pick up exactly where you left off.

No backend

Ship a static page with two headers. Nothing to deploy, secure or scale on the server side.

Drop it into your app

One dependency, a few lines, and your page can run Node.

import { boot } from "wcvm";

const wc = boot();
await wc.ready;

await wc.fs.writeFile("/hello.js", `console.log("hello from", process.version)`);

const proc = await wc.spawn("node", ["hello.js"]);
console.log(await new Response(proc.stdout).text());  // hello from v24.18.0
await wc.fs.mount({
  "package.json": { file: { contents: '{"name":"app"}' } },
  src: {
    directory: {
      "main.js": { file: { contents: "console.log(1)" } },
    },
  },
}, "/app");

const text = new TextDecoder().decode(await wc.fs.readFile("/app/src/main.js"));
await wc.fs.sync();  // everything is on disk (OPFS) if boot({ persist: true })
await wc.preview.enable();

wc.preview.onListen(({ port, listening }) => {
  if (listening) iframe.src = wc.preview.url(port);
});

await wc.spawn("npm", ["install"], { cwd: "/app" });
await wc.spawn("npm", ["run", "dev"], { cwd: "/app" });

How it works

A blocked call is Atomics.wait on a SharedArrayBuffer: the worker parks, another worker answers and wakes it. That one trick lets Node's synchronous APIs run in a browser.

Questions, answered

Is this real Node.js?

It runs Node v24's own JavaScript lib/, unmodified, on a native layer written for the browser, so fs, streams, http, child_process and ESM behave like Node. It is not full Node: native add-ons (.node files) cannot load, and a few modules such as crypto are partial.

Does it need a server?

No. It is a static page that sends two headers (cross-origin isolation, needed for SharedArrayBuffer). npm install does need to reach the npm registry from the visitor's browser.

Which browsers does it support?

It needs cross-origin isolation and SharedArrayBuffer. It is developed and tested in Chromium; other modern browsers with those features should work but are not covered by the test suite yet.

Which frameworks run?

Vite (React, Vue, Svelte, Preact, Lit, Solid, Qwik), Tailwind v4, Next.js, SvelteKit, React Router 7, Astro, Angular, Ember, Express and NestJS. Each is installed from the real registry and served in real Chromium by the project's end-to-end tests. Nuxt and Vite 8 do not run yet.

How big is it?

The npm package is about 700 kB compressed. The largest piece is the process worker (about 2.4 MB unpacked) that carries Node's runtime.

Is it free?

Yes. wcvm is open source under the ISC license, and its bundled Node.js sources are MIT licensed.
